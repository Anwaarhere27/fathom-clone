# Cadence Notes

A rebuild of [fathom.video](https://fathom.video) — the AI meeting notetaker — built in a day.

**Live:** https://fathom-clone-dun.vercel.app
**Repo:** https://github.com/Anwaarhere27/fathom-clone

The live link opens without an account. **Try the demo** drops you into a workspace with
five real meetings already recorded, transcribed and summarised — 2 hours 36 minutes of
audio, 815 transcript segments, including an eight-person call that runs fifty-six minutes.

---

## What it does

| | |
|---|---|
| **Playback + synced transcript** | Speaker-labelled, word-timestamped. Click any line to jump there; the transcript follows as it plays. |
| **Summaries that switch shape** | The same call read as a discovery call, a standup, an all-hands. Switching template reorganises the meeting, it does not reword it. |
| **Action items** | Who committed to what, when they said it, and a timestamp back to the moment. |
| **Clips anyone can open** | Mark a moment, send the link. It opens for someone with no account, bounded to the clip. |
| **Search across everything** | One query over every transcript, landing on the exact second. |
| **Ask AI** | Questions answered across your whole history, with citations you can click and check. |
| **Upload a recording** | A Zoom file a client emailed you, a voice memo, a webinar download. |
| **Record live** | Capture a call from the browser — your mic, optionally mixed with the meeting tab's audio. |
| **Talk time** | Share of the conversation, plus a timeline of when each person actually spoke. |
| **Follow-up email** | Drafted from what was agreed, ready to send. |
| **Calendar** | Real Google OAuth, upcoming meetings, per-meeting record toggles. |

---

## What is real and what is not

**Real:** every transcript, summary, action item, follow-up email and answer on the site was
generated by an open-weight model. Nothing is hand-written. Upload and live recording run the
same pipeline at request time — upload a file and watch it transcribe. Google Calendar is a real
OAuth integration. Share links are genuinely public.

**Not real — and deliberately so:** there is no bot that dials into Zoom, Meet or Teams.

That bot is the hardest twenty percent of Fathom and the least interesting to rebuild: surviving
waiting rooms, capturing system audio in a headless browser, staying joined for an hour. It is an
infrastructure project, not a feature, and the assignment explicitly allows stubbing the capture
layer. Rather than *simulate* a bot — which would demo a flow with nothing behind it — capture is
replaced with two paths that actually work:

- **Record from the browser.** Your microphone, optionally mixed with the meeting tab's audio via
  `getDisplayMedia`. This is a real recording of a real call.
- **Upload a file.** Which Fathom cannot do at all, and which was the most common complaint I
  found while using it.

**The seeded meetings are synthetic**, and the walkthrough says so. Transcripts were written by
`gpt-oss-120b` from meeting outlines, then spoken by [Piper](https://github.com/rhasspy/piper)
with a distinct voice per participant. They are fiction, but they are *specific* fiction —
contract clauses, availability percentages, SLA credits — because a summariser can only be judged
against content that has something to summarise.

## Stack

- **Next.js 16** (App Router, Turbopack) on Vercel
- **Supabase** — Postgres, Auth, Storage
- **Groq** serving open-weight models only: `gpt-oss-120b` / `gpt-oss-20b` (Apache 2.0),
  `qwen3.8-27b`, and `whisper-large-v3-turbo` for transcription
- **Piper** (MIT) for the seeded voices, run locally on CPU

No closed model is used anywhere in the product.

---

## Decisions worth explaining

**Summary template headings are fixed in code, not chosen by the model.** Ask a model to
"summarise this as a sales discovery call" and you get the same summary with different adjectives.
Pin the headings — *Pain and current state*, *Objections raised*, *Budget, timeline and process* —
and switching template genuinely reorganises the call. That is the difference between the feature
being real and being a prompt trick.

**Summarisation is map-reduce, out of necessity.** The free tier allows 8,000 tokens per minute
counting input *and reserved output together*. The 56-minute QBR is ~12k tokens of transcript, so
it cannot go into one request. Chunks are condensed into notes that preserve every number, name
and `[Ns]` timestamp; the template passes run over the notes. The notes are then reduced
*iteratively in windows* — the first attempt was a single "merge these notes" request, which was
itself too large to send. The fix for *request too large* cannot be one more large request.

**The model returns a flat bullet list, not nested sections.** Asked for
`sections: [{heading, bullets: [...]}]` it produced excellent content in invalid JSON — one extra
`]}` per section — and JSON mode rejects the whole generation over it. A flat list with a section
label per bullet is something it gets right every time; grouping happens in code. When JSON mode
does reject, the text still arrives on the error object, so it is re-balanced and salvaged rather
than regenerated.

**Seed audio is synthesised per turn, then concatenated.** A transcript line's timestamp is the
sum of the real durations before it, not an estimate from word count. Estimates drift; by the
fifty-minute mark of the QBR they would be tens of seconds out, and clicking a line would land you
in the wrong part of the conversation.

**Search is Postgres full-text, not a vector store.** The corpus is one person's meetings and the
questions are about things literally said. Keeping it in the database means no embedding pipeline
to keep in sync, and Ask AI retrieves over the same index — so the model only ever sees lines from
your own recordings and cannot answer from outside them.

**Every "Try the demo" visitor gets their own cloned workspace.** A shared demo account means two
people on the link at once edit the same rows — one marks an action item done, the other watches
it happen. Cloning costs one function call.

**Speaker attribution on uploads is a guess, and says so.** Whisper transcribes but does not
diarize, and no hosted open-weight model offers speaker separation. The model infers turn changes
from the shape of the conversation. Rather than present that as ground truth, the UI labels it.

## What was cut

Team workspaces, playlists, alerts, the Deals/CRM surface, and the recording bot. Fathom has all
of them; none would have made the product better to *use* in the time available, and the brief
scores what you chose to build first.

## Running it

```bash
npm install
cp .env.example .env.local     # then fill in the values
npm run migrate                # applies supabase/migrations
npm run dev
```

Environment variables:

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Public anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-only. Share pages and seeding. |
| `SUPABASE_DB_PASSWORD` | Used by the migration script |
| `GROQ_API_KEY` | Inference |
| `GROQ_TEXT_MODEL` | Optional model override |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Calendar OAuth |
| `NEXT_PUBLIC_SITE_URL` | OAuth redirects and share links |

### Rebuilding the seed

```bash
npm run seed:generate     # transcripts from the outlines in scripts/seed/blueprints.mjs
npm run seed:setup-tts    # downloads Piper + voice models (~500 MB, gitignored)
npm run seed:audio        # synthesises per turn, stitches, derives exact timings
npm run seed:load         # uploads audio, writes meetings and transcripts
npm run seed:summarize    # summaries, action items, follow-up emails
```

---

## `.agent-logs/`

Committed, as required. One caveat: the capture hook records whatever is pasted into the
conversation, including API keys. `npm run redact` scrubs known secret shapes plus any sensitive
value found in `.env.local`, and runs before every commit. GitHub's push protection caught this on
the first push, which is how it got built.

## Known limits

- Speaker attribution on uploads is inferred, not diarized.
- Uploads are capped at 25 MB, which is the transcription API's limit.
- Google OAuth is unverified, so the consent screen warns about it and refresh tokens expire after
  seven days. Judges never hit this — the demo workspace has calendar data already.
- Free-tier inference has a daily token budget. Everything seeded is pre-generated, so the demo is
  instant, but heavy live use of Ask AI or upload can exhaust it. The UI says so rather than
  failing silently.
